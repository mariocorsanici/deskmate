# Agenda Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve non-development commitments and tasks and account for them in the daily loop.

**Architecture:** One standard-library CLI owns `data/agenda.md`, locking, parsing and archiving. Skills translate natural language into its commands and render its output. Keep core, new skill and each existing-skill integration in separate commits; ticket 06 waits for the other branch's prerequisites.

**Tech Stack:** Python standard library, unittest, Markdown skills, existing zsh installer/hooks.

**Spec:** `.scratch/agenda/spec.md`; approved coordination: `.scratch/agenda/coordination.md`.

## Global Constraints

- Python standard library only, invoked with `python3 -I`.
- `data/agenda.md` is written only through `tools/agenda.py`; existing personal data is never overwritten by installation.
- Support `config.json` language `it` and `en`.
- Preserve unrelated bytes and invalid lines; diagnostics go to stderr so list stdout remains machine-readable.
- Exit codes: 0 clean, 1 usage/no write, 2 invalid lines after successful work, 3 whole non-development day; for `is-dev-day`, 3 wins over 2.
- Lock `data/.agenda.lock`; archive `data/archive/agenda-YYYY-MM.md`.
- Do not merge or alter the other agents' branches. Ticket 06 remains blocked until its prerequisites reach develop.

## Review Focus

- Configuration language changes: existing Italian and English entries remain readable, with original bytes preserved.
- Newline/metadata injection: reject descriptions that cannot round-trip as a single agenda entry, without changing the file.
- Historical non-development days: archiving must not make `is-dev-day` forget them.
- Concurrent first use and updates: no lost entries or partially written files.
- Read-only installation initialization: an existing agenda remains byte-identical across repeated initialization.

## Decisions for the CLI

`list` stdout is one JSON object with keys `today`, `due`, `deadline`, `undated`, `upcoming`, `closed`. All keys except `undated` contain lists of original entry lines; `undated` is an integer. Notices and invalid-line diagnostics are stderr. `closed` is populated only with `--closed-since`.

Working-day windows mean Monday through Friday, with no holiday calendar: use the date of the third/fifth following weekday as the inclusive bound, and include weekend commitments within that range. `archive` without `--closed-before` archives past days only. Closed tasks are grouped by completion month. `is-dev-day` also reads the archive for the requested month, preserving the meaning of past dates. `done --today YYYY-MM-DD` supplies its completion date for deterministic tests.
